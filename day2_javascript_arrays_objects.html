01 Arrays — structure, mutation, and core methods foundation
what arrays are
Ordered, zero-indexed lists
Arrays hold values in a specific order, accessed by index starting at 0. They are actually objects under the hood — typeof [] === "object". Use Array.isArray() to check. Length updates automatically. Arrays can hold mixed types, though this is rarely a good idea in real code.
mutation trap
Mutating vs non-mutating methods
Some array methods mutate the original (push, pop, sort, splice, reverse). Others return a new array (map, filter, slice, concat, spread). In React, you must never mutate state directly — always use non-mutating patterns. Knowing which methods mutate is essential to avoid bugs.
mental model
Arrays as data pipelines
Think of array methods as pipeline stages: your data flows through a series of transforms. Each method returns a new array, so you can chain them. This pattern — immutable transformations chained together — is the core mental model of both functional JavaScript and React state updates.

  { id: 2, product: "Mouse",   price: 29,   qty: 3 },
  { id: 3, product: "Monitor", price: 349,  qty: 2 },

// Simple extraction
const productNames = orders.map(o => o.product)
// ["Laptop", "Mouse", "Monitor"]

  ...o,
  total: o.price * o.qty

// Each order now has a total field. Original array unchanged.

// Using index parameter
const numbered = orders.map((o, i) => `${i + 1}. ${o.product}`)
// ["1. Laptop", "2. Mouse", "3. Monitor"]

// React pattern — render JSX from data (what you'll write every day)
// orders.map(order => <OrderCard key={order.id} {...order} />)

javascriptreduce — the Swiss Army knife
// .reduce(callback, initialValue)
// callback receives: (accumulator, currentValue, index, array)
// accumulator = running result. initialValue = what it starts as.

const cart = [
  { name: "Book",     price: 15, qty: 2 },
  { name: "Notebook", price: 8,  qty: 3 },
  { name: "Pen",      price: 3,  qty: 5 },
]

// 1. Sum — reduce to a number
const total = cart.reduce((sum, item) => sum + item.price * item.qty, 0)
// 0 + (15*2) + (8*3) + (3*5) = 0 + 30 + 24 + 15 = 69

// 2. Group by — reduce to an object (very common pattern)
const transactions = [
  { type: "food",      amount: 45 },
  { type: "transport", amount: 20 },
  { type: "food",      amount: 30 },
  { type: "transport", amount: 15 },
  { type: "leisure",   amount: 60 },
]

const byCategory = transactions.reduce((acc, t) => {
  acc[t.type] = (acc[t.type] || 0) + t.amount
  return acc
}, {})
// { food: 75, transport: 35, leisure: 60 }

// 3. Flatten array of arrays
const nested    = [[1, 2], [3, 4], [5]]
const flat      = nested.reduce((acc, arr) => [...acc, ...arr], [])
// [1, 2, 3, 4, 5]  (or just use .flat())

// 4. Build a lookup map (id → object) — massive performance gain
const users = [{ id: 1, name: "Alice" }, { id: 2, name: "Bob" }]
const usersById = users.reduce((acc, u) => ({ ...acc, [u.id]: u }), {})
// { 1: { id:1, name:"Alice" }, 2: { id:2, name:"Bob" } }
// Now: usersById[1] → user in O(1) instead of O(n) find()

// 5. Pipeline of transforms (advanced but elegant)
const pipeline = [double, addTen, square]
const result   = pipeline.reduce((val, fn) => fn(val), 5)
// Runs: square(addTen(double(5))) = square(addTen(10)) = square(20) = 400
javascriptother essential methods + method chaining
const employees = [
  { name: "Alice", dept: "eng",     salary: 95000, active: true  },
  { name: "Bob",   dept: "design",  salary: 82000, active: true  },
  { name: "Carol", dept: "eng",     salary: 110000,active: false },
  { name: "Dan",   dept: "design",  salary: 78000, active: true  },
  { name: "Eve",   dept: "eng",     salary: 105000,active: true  },
]

// .find() — first match or undefined
const designer = employees.find(e => e.dept === "design")   // Bob
const notFound = employees.find(e => e.dept === "sales")    // undefined

// .findIndex() — index of first match or -1
const idx = employees.findIndex(e => e.name === "Carol")   // 2

// .some() / .every() — boolean tests
employees.some(e  => e.salary > 100000)   // true — at least one earns > 100k
employees.every(e => e.active)            // false — not all are active

// .sort() — mutates! spread first for React safety
const sorted = [...employees].sort((a, b) => b.salary - a.salary)
// Sorted high→low salary. Original unchanged.

// .flat() / .flatMap()
const tags     = [["js", "react"], ["css"], ["node", "ts"]]
const allTags  = tags.flat()               // ["js","react","css","node","ts"]
const doubled  = [1, 2, 3].flatMap(n => [n, n * 2])  // [1,2,2,4,3,6]

// CHAINING — the real power (read top to bottom like a sentence)
const topEngNames = employees
  .filter(e => e.dept === "eng" && e.active)     // active engineers only
  .sort((a, b) => b.salary - a.salary)            // sort by salary desc
  .slice(0, 2)                                       // top 2
  .map(e => e.name)                                  // extract names
// ["Eve", "Alice"]
03 Objects — deep dive, patterns and prototype daily use
key patterns
Object creation patterns
Object literal {} — by far the most common. Object.create(proto) — creates object with specific prototype. Constructor function / class — when you need many objects of the same shape. Factory function — returns plain objects, no new needed. In React, you'll use object literals and factory functions almost exclusively.
key methods
Object utility methods
Object.keys(obj) — array of property names. Object.values(obj) — array of values. Object.entries(obj) — array of [key, value] pairs. Object.assign(target, src) — shallow merge. Object.freeze(obj) — make immutable. These come up in interviews and real data transforms constantly.
important
Shallow vs deep copy
Spread ({...obj}) and Object.assign create shallow copies — nested objects are still references. If you need a true independent copy at all depths, use structuredClone(obj) (modern, built-in) or JSON.parse(JSON.stringify(obj)) (older hack, loses functions/dates). In practice, Immer handles this in React apps.

  ...config,
  headers: { ...config.headers, Authorization: "Bearer newtoken" }

javascriptEvery destructuring pattern you'll use in production

const user = {
  id: 42, name: "Alice", role: "admin",
  address: { city: "Austin", state: "TX", zip: "78701" },
  scores: [88, 92, 76]

// Basic extraction
const { name, role } = user

// Rename while destructuring
const { name: fullName, id: userId } = user

// Default value (used when property is undefined)
const { name, avatar: pic = "default.png", premium = false } = user

// Nested destructuring
const { address: { city, state } } = user
// city → "Austin", state → "TX"

// Rest in object destructuring (collect remaining props)
const { id, name, ...rest } = user
// rest → { role, address, scores } — everything except id and name

// ── ARRAY DESTRUCTURING ───────────────────────────────────────────

const [first, second, third] = [10, 20, 30]

// Skip elements with commas
const [, second, , fourth] = [10, 20, 30, 40]

// Default values
const [x = 0, y = 0, z = 0] = [5, 10]  // z → 0

// Rest in array destructuring
const [head, ...tail] = [1, 2, 3, 4]
// head → 1, tail → [2, 3, 4]

// Swap variables — no temp variable needed
let a = 1, b = 2
;[a, b] = [b, a]   // a → 2, b → 1

}

// Nested in params
const formatAddress = ({ address: { city, state, zip: postal } }) =>
  `${city}, ${state} ${postal}`

05 Spread & Rest — same syntax, opposite directions essential
Mental model: spread expands, rest collects
Spread (...)
Expands an iterable into individual values. Used when calling functions or building arrays/objects.
Rest (...)
Collects multiple values into a single array or object. Used in function parameters and destructuring.
Same syntax
Both use .... Context determines which it is: left side of assignment = rest. Right side = spread.
Key rule
Rest parameter must be last. (...a, b) is invalid. Only one rest per destructure.

06 Optional chaining · Nullish coalescing · Short-circuit defensive coding
javascriptSafe property access patterns — essential for real APIs
// The problem: deeply nested API data that might be partially missing
const response = {
  data: {
    user: {
      profile: {
        name: "Alice",
        social: { twitter: "@alice" }  // instagram is missing
      }
      // settings is missing entirely
    }
  }
}

// Old way — verbose and crashes on undefined
const name1 = response &&
              response.data &&
              response.data.user &&
              response.data.user.profile &&
              response.data.user.profile.name

// Modern way — optional chaining (?.) — returns undefined instead of throwing
const name2     = response?.data?.user?.profile?.name
const twitter   = response?.data?.user?.profile?.social?.twitter  // "@alice"
const instagram = response?.data?.user?.profile?.social?.instagram // undefined (no crash)
const darkMode  = response?.data?.user?.settings?.darkMode         // undefined (no crash)

// Optional chaining with methods
const upper     = response?.data?.user?.profile?.name?.toUpperCase()  // "ALICE"
const result    = obj?.compute?.()   // call method only if obj exists and compute is a function

// Optional chaining with arrays
const firstTag  = post?.tags?.[0]   // safe array access

// ── NULLISH COALESCING (??) ───────────────────────────────────────
// Returns right side only when left side is null OR undefined
// (Unlike || which returns right side for ANY falsy value)

const theme  = userPref ?? "light"   // "light" only if userPref is null/undefined
const count  = data.count ?? 0       // 0 if count is null/undefined — NOT if it's 0!
const label  = item.label ?? ""       // "" if null/undefined — NOT if label is ""

// Critical difference from ||
const score  = 0
score || 100    // 100  ← wrong! 0 is falsy, falls to right side
score ?? 100    // 0   ← correct! 0 is a valid value, not null/undefined

// Combine optional chaining + nullish coalescing (the power combo)
const displayName = user?.profile?.displayName ?? user?.name ?? "Anonymous"
const pageSize    = config?.pagination?.pageSize  ?? 20
const userCity    = response?.data?.user?.address?.city ?? "Unknown"

// Nullish assignment (??=) — assign only if currently null/undefined
user.bio    ??= "No bio provided"
config.timeout ??= 5000

09 Interview questions + model answers interview prep
Q1What is the difference between map, filter, and forEach? Why doesn't forEach get chained?▶
model answer
map transforms every element and returns a new array of the same length. filter keeps only elements where the callback returns truthy, returning a new shorter array. forEach iterates for side effects only — it always returns undefined, so it cannot be chained.

Why forEach can't chain: chaining works because each method returns an array. forEach returns undefined, so calling .map() after it would throw a TypeError. Use forEach only for side effects (logging, DOM updates, API calls) where you don't need the result array. For everything transformative, use map or filter.
Depth signal: mention that using map for side effects (logging inside map) is a code smell — it confuses intent and returns an array of undefined values that nobody uses.
Q2Explain how reduce works. What is the accumulator and what happens if you omit the initial value?▶
model answer
reduce(callback, initialValue) iterates the array, calling the callback on each element with two main arguments: the accumulator (the running result) and the current value. The return value of each callback call becomes the accumulator for the next iteration. The final accumulator is what reduce returns.

Without initialValue: the first element becomes the accumulator and iteration starts from index 1. On an empty array this throws a TypeError. Always provide an initial value — it makes the function's intent clear and prevents crashes. Initial value also determines the return type: [] → map, {} → groupBy, 0 → sum.
Strong answer: "I use reduce when I need to collapse an array into something that isn't another array — a sum, an object keyed by ID, a grouped structure. If the output is still an array, I reach for map or filter first."
Q3Why does mutating arrays matter in React? How do you add, update, and remove items from state?▶
model answer
React detects state changes by comparing object references. If you mutate an array directly (arr.push(item), arr[0] = x), the reference stays the same — React sees the same object and skips re-rendering. This creates bugs where the UI doesn't update even though your data changed.

The solution is always return a new array:
— Add: [...prev, newItem]
— Remove: prev.filter(item => item.id !== targetId)
— Update: prev.map(item => item.id === id ? {...item, ...changes} : item)

These patterns are safe because each creates a new array reference, which React can detect.
Common mistake: const arr = [...state]; arr.push(x); setState(arr) — the push mutates arr, but since setState receives a new reference it still works. However this habit will cause bugs in more complex scenarios. Always compute the new array without mutation.
Q4What is object destructuring? How does renaming and setting defaults work?▶
model answer
Destructuring is ES6 syntax that extracts properties from an object into local variables in a single expression. It reduces repetition and makes component props more readable.

Renaming: const { firstName: name } = user — the property is firstName but the local variable is named name. The colon separates "source property" from "local variable name".

Default values: const { role = "user" } = person — if role is undefined, it defaults to "user". Defaults only apply for undefined, not for null or "".

Combined: const { user_id: id = 0 } = data — extract user_id, rename to id, default to 0.
Q5What is the spread operator? What does "shallow copy" mean and when is it a problem?▶
model answer
The spread operator (...) expands an iterable's elements. For objects it copies own enumerable properties into a new object. For arrays it copies elements into a new array.

Shallow copy means top-level primitive values are copied by value, but nested objects and arrays are still copied by reference — both the original and the copy point to the same nested object.

This becomes a problem with nested state in React: const newState = {...state} — if you then do newState.user.name = "Bob", you've also mutated state.user.name because user is a shared reference. Fix: spread at every level — {...state, user: {...state.user, name: "Bob"}} — or use structuredClone() for full deep copy.
Q6What is the difference between rest and spread? Give an example of each in context.▶
model answer
Same syntax (...), opposite directions. Spread expands a collection into individual elements — used on the right side when building arrays/objects or passing arguments. Rest collects multiple individual values into a single array or object — used on the left side in destructuring or in function parameters.

Context determines which it is: fn(...args) is spread (expanding array into args). function fn(...args) is rest (collecting individual args into array). const [first, ...rest] = arr is rest in destructuring. [...arr, newItem] is spread into array literal.
Memorable one-liner: "Spread breaks things apart. Rest bundles things together."
Q7What does optional chaining (?.) do? How does it differ from checking with &&?▶
model answer
Optional chaining short-circuits and returns undefined if the value before ?. is null or undefined, instead of throwing a TypeError. It safely accesses nested properties, array indices, and method calls.

vs &&: user && user.profile && user.profile.name also short-circuits, but returns the falsy value itself when the check fails — so if user is 0 or "", it returns those falsy values rather than continuing. Optional chaining only stops on null or undefined — making it safer for data that might legitimately be 0 or false.
Q8What is the difference between ?? (nullish coalescing) and || (logical OR) for default values?▶
model answer
|| returns the right side when the left side is any falsy value — including 0, "", and false. ?? only returns the right side when the left is specifically null or undefined.

This matters when 0, "", or false are valid values: count || 10 gives 10 when count is 0 — probably wrong. count ?? 10 gives 0 — correct. Use ?? for "provide a default when nothing was set" and || for "provide a fallback when the value is considered empty".
Gotcha in the wild: a form field that allows the user to enter 0 or an empty string — using || as a default will override their valid input. Always use ?? for form field defaults.
Q9How do you sort an array of objects by a property? What are the gotchas with .sort()?▶
model answer
.sort(compareFn) sorts in-place. The compare function returns a negative number (a before b), 0 (equal), or positive (b before a).

Number sort: (a, b) => a.price - b.price (ascending). (a, b) => b.price - a.price (descending).

String sort: (a, b) => a.name.localeCompare(b.name) — handles accents and locale correctly. Don't use a.name < b.name ? -1 : 1 — it fails for equal strings and doesn't handle locale.

Gotchas: 1) mutates the original array — always spread first in React: [...arr].sort(...). 2) Without a compareFn, sort converts elements to strings — [10, 9, 100].sort() gives [10, 100, 9]. Always provide compareFn for non-string arrays.
Q10How would you convert an array of objects into a lookup map keyed by ID? Why would you do this?▶
model answer
Use reduce with an empty object as the initial value:
const map = users.reduce((acc, u) => ({...acc, [u.id]: u}), {})

Or more efficiently (avoids creating many intermediate objects):
const map = Object.fromEntries(users.map(u => [u.id, u]))

Why: looking up an item in an array with find() is O(n) — it scans the whole array each time. A lookup map gives O(1) access: map[userId]. In a component that renders a list and frequently needs to look up details by ID (e.g. connecting order IDs to user objects), converting to a map once can improve performance from O(n²) to O(n).

This is a very common pattern in Redux stores, React Query caches, and normalised state structures.
