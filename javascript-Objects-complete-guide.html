Core JavaScript

Variables, scope, hoisting, closures — the non-negotiable bedrock.

var · let · const
Beginner
Old way — var
• Function-scoped (not block)
• Hoisted & initialized to undefined
• Can be re-declared freely
• Leaks outside if/for blocks
Modern — let / const
• Block-scoped (stays inside {})
• Hoisted but NOT initialized (TDZ)
• let reassignable, const is not
• Predictable, preferred always
// Temporal Dead Zone — accessing let before declaration throws
// console.log(x); → ReferenceError (TDZ)
let x = 10;

// Classic var loop bug
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100); // 3 3 3 — bug!
}
// Fix: replace var with let — each iteration gets its own i
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100); // 0 1 2 ✓
}
Real scenario: In a React component rendering a list of buttons, using var in the handler loop means every button alerts the same index. Switching to let or using the loop variable in a closure fixes it instantly.
Closures
Mid-level

A closure is a function that "remembers" the variables from the scope where it was created, even after that outer function has returned.

function makeCounter(start = 0) {
  let count = start;            // private — not accessible outside
  return {
    increment: () => ++count,
    decrement: () => --count,
    reset:     () => { count = start; },
    value:     () => count
  };
}

const counter = makeCounter(10);
counter.increment();  // 11
counter.increment();  // 12
counter.reset();      // back to 10

// Closure for memoization (caching)
function memoize(fn) {
  const cache = new Map();
  return function(...args) {
    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key);
    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}
Real scenario: React's useState, useCallback, and useMemo all rely on closures to preserve state between renders. Node.js request handlers close over req/res. Event emitters capture outer scope data.

4 ways to define a function
Beginner
// 1. Declaration — hoisted fully, has own 'this'
function greet(name) { return `Hello, ${name}`; }

// 2. Expression — not hoisted, assigned like a value

// 4. IIFE — Immediately Invoked Function Expression

  const private = 'only here';

Currying & partial application
Mid-level
// Currying: f(a, b, c) → f(a)(b)(c)
const multiply = a => b => a * b;
const triple = multiply(3);
triple(5);  // 15
triple(7);  // 21

// Generic curry utility
const curry = fn => {
  const arity = fn.length;
  return function curried(...args) {
    if (args.length >= arity) return fn(...args);
    return (...more) => curried(...args, ...more);
  };
};

const add = curry((a, b, c) => a + b + c);
add(1)(2)(3);  // 6
add(1, 2)(3); // 6
Real scenario: In a React app, currying lets you pre-configure handlers: const handleChange = field => event => dispatch({ field, value: event.target.value }). Each field gets its own handler without repetition.

Objects & Schema Comparison

Object creation, shape validation, deep equality, schema diffing — the article concept explained.

What is an "object schema"?
Mid-level

A schema is a plain JS object that describes the shape of another object — its keys, expected types, required fields, and constraints. It's a blueprint you can compare real data against.

// ── Schema definition (blueprint object) ──
const userSchema = {
  id:       { type: 'number',  required: true  },
  name:     { type: 'string',  required: true  },
  email:    { type: 'string',  required: true  },
  age:      { type: 'number',  required: false },
  isAdmin:  { type: 'boolean', required: false },
  role:     { type: 'string',  required: false, enum: ['user','admin','mod'] },
};

// ── Validator function ──
function validate(data, schema) {
  const errors = [];
  for (const [key, rule] of Object.entries(schema)) {
    const val = data[key];
    if (rule.required && val === undefined)
      errors.push(`Missing required field: "${key}"`);
    else if (val !== undefined && typeof val !== rule.type)
      errors.push(`"${key}" must be ${rule.type}, got ${typeof val}`);
    else if (rule.enum && val && !rule.enum.includes(val))
      errors.push(`"${key}" must be one of [${rule.enum.join(', ')}]`);
  }
  return { valid: errors.length === 0, errors };
}
Schema Comparison — comparing two schemas (versioning)
Architecture
// Deep equality — compare two plain objects recursively
function deepEqual(a, b) {
  if (a === b) return true;
  if (typeof a !== 'object' || typeof b !== 'object') return false;
  if (a === null || b === null) return false;
  const [ka, kb] = [Object.keys(a), Object.keys(b)];
  if (ka.length !== kb.length) return false;
  return ka.every(k => deepEqual(a[k], b[k]));
}

// Schema diff — find what changed between v1 and v2
function schemaDiff(s1, s2) {
  const keys = new Set([...Object.keys(s1), ...Object.keys(s2)]);
  const diff = { added: [], removed: [], changed: {} };
  for (const k of keys) {
    if      (!s1[k])                    diff.added.push(k);
    else if (!s2[k])                    diff.removed.push(k);
    else if (!deepEqual(s1[k], s2[k])) diff.changed[k] = { from: s1[k], to: s2[k] };
  }
  return diff;
}

// Example — API versioning
const schemaV1 = {
  name:  { type: 'string', required: true  },
  age:   { type: 'number', required: false },
};
const schemaV2 = {
  name:  { type: 'string', required: true  },
  age:   { type: 'string', required: true  }, // type changed! breaking
  email: { type: 'string', required: true  }, // added
};
schemaDiff(schemaV1, schemaV2);
// { added: ['email'], removed: [], changed: { age: { from: {...}, to: {...} } } }
Real scenario: When your backend team evolves the User API from v1 to v2, run schemaDiff(schemaV1, schemaV2) in CI. It instantly catches breaking changes (type mismatches, removed required fields) before they reach production.

Prototype & OOP

The prototype chain, constructor functions, Object.create — pre-class patterns.

Prototype chain
Mid-level
// Every JS object has a hidden [[Prototype]] link
const animal = {
  breathe() { return `${this.name} breathes`; }
};
const dog = Object.create(animal);  // dog.__proto__ === animal
dog.name = 'Rex';
dog.breathe();  // "Rex breathes" — inherited from animal

// Property lookup order:
// dog → animal → Object.prototype → null
dog.hasOwnProperty('name');    // true  — own
dog.hasOwnProperty('breathe'); // false — inherited

// Constructor function pattern (pre-class)
function Animal(name) { this.name = name; }
Animal.prototype.speak = function() { return `${this.name} speaks`; };
const cat = new Animal('Whiskers');
cat.speak(); // "Whiskers speaks"

Classes & Inheritance

ES6 classes are syntactic sugar over prototypes — understand what's underneath.

Class syntax & inheritance
Mid-level
class Animal {
  #name;                     // private field (ES2022)

  constructor(name) {
    this.#name = name;
  }

  get name()   { return this.#name; }
  speak()      { return `${this.#name} makes a sound`; }
  static create(name) { return new this(name); }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name);           // must call super first
    this.breed = breed;
  }

  speak() {
    return `${super.speak()} — Woof!`;
  }
}

const d = new Dog('Rex', 'Labrador');
d.speak();               // "Rex makes a sound — Woof!"
d instanceof Dog;        // true
d instanceof Animal;     // true
Real scenario: In a Node.js REST API, you might have a base Repository class with findById, create, update, and delete methods. UserRepository and ProductRepository extend it with entity-specific logic.

Promise patterns
Mid-level
// async/await — clean sequential async code
async function fetchUser(id) {
  try {
    const res  = await fetch(`/api/users/${id}`);
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    const user = await res.json();
    return user;
  } catch (err) {
    console.error('Fetch failed:', err);
    throw err;  // re-throw for caller to handle
  }
}

// Run in parallel — Promise.all
const [user, posts] = await Promise.all([
  fetchUser(1),
  fetch('/api/posts').then(r => r.json())
]);

// First to succeed — Promise.any
const fastest = await Promise.any([server1(), server2()]);

// All settled (never throws) — Promise.allSettled
const results = await Promise.allSettled([a(), b(), c()]);
results.filter(r => r.status === 'fulfilled');
Real scenario: A dashboard page needs user data, recent orders, and analytics. Use Promise.all to fire all three requests simultaneously — cutting load time from 900ms (sequential) to ~300ms (parallel).

Observer Pattern
Architecture
class EventBus {
  #events = new Map();

  on(event, cb) {
    if (!this.#events.has(event))
      this.#events.set(event, new Set());
    this.#events.get(event).add(cb);
    return () => this.off(event, cb); // unsubscribe fn
  }

  off(event, cb) { this.#events.get(event)?.delete(cb); }

  emit(event, data) {
    this.#events.get(event)?.forEach(cb => cb(data));
  }
}

const bus = new EventBus();
const unsub = bus.on('order:placed', order =>
  console.log('New order:', order));
bus.emit('order:placed', { id: 42, total: 150 });
unsub(); // clean up

Strategy Pattern
Architecture
const sortStrategies = {
  price:  (a, b) => a.price - b.price,
  name:   (a, b) => a.name.localeCompare(b.name),
  rating: (a, b) => b.rating - a.rating,
};

function sortProducts(products, strategy = 'price') {
  const comparator = sortStrategies[strategy];

}

Proxy Pattern
Architecture
function createReactive(target, onChange) {
  return new Proxy(target, {
    set(obj, key, value) {
      const old = obj[key];
      obj[key] = value;
      if (old !== value) onChange({ key, old, value });
      return true;
    },
    get(obj, key) {
      if (typeof obj[key] === 'function')
        return obj[key].bind(obj);
      return obj[key];
    }
  });
}

const state = createReactive({ count: 0 }, console.log);
state.count = 5; // logs: { key: 'count', old: 0, value: 5 }
// This is how Vue 3's reactivity system works!

Beginner
Beginner
Q
What is the difference between == and ===?
== (loose equality) coerces types before comparing: 0 == "" is true. === (strict equality) requires identical types and values: 0 === "" is false. Always prefer === unless you explicitly want coercion (rare). Special case: null == undefined is true with ==, useful for checking both at once.
Q
What is hoisting?
During compilation, JS moves declarations to the top of their scope. var declarations are hoisted and initialized to undefined. function declarations are hoisted fully (you can call them before they appear). let/const are hoisted but NOT initialized — accessing them before declaration throws a ReferenceError (the Temporal Dead Zone).
Q
What are falsy values in JavaScript?
There are exactly 8 falsy values: false, 0, -0, 0n (BigInt zero), ""/''/`` (empty string), null, undefined, NaN. Everything else is truthy — including [], {}, and "0".
Q
Difference between null and undefined?
undefined means a variable was declared but never assigned a value (or a function returned nothing). null is an intentional assignment meaning "no value here". typeof null === "object" is a famous historical bug. Use value == null to catch both.
Mid-level
Mid-level
Q
Explain closures with a practical use case.
A closure is a function that remembers the outer scope in which it was created. Practical example — memoization:
function memoize(fn) {
  const cache = {};          // closed over
  return (...args) => {
    const k = JSON.stringify(args);
    return cache[k] ??= fn(...args);
  };
}
The cache object persists across calls because the returned function closes over it. React hooks, private module state, and debounce/throttle all use closures.
Q
What is the event loop and how does JS handle async?
JS is single-threaded. The event loop lets it handle async without blocking: sync code runs on the Call Stack; async operations (fetch, setTimeout) are offloaded to Web APIs. When done, their callbacks go to the Callback Queue (macrotasks) or Microtask Queue (Promises). Microtasks always drain fully before the next macrotask. Order: sync → microtasks → macrotask → microtasks → …
Q
What is prototypal inheritance?
JS objects have a hidden [[Prototype]] link to another object. When a property is not found on the object itself, JS walks up the chain until it finds it or reaches null. class syntax is sugar over this. Object.create(proto) lets you set the prototype explicitly. Methods placed on prototype are shared across all instances (memory-efficient).
Q
Difference between call, apply, and bind?
All three set the this context of a function. call(ctx, a, b) invokes immediately with comma-separated args. apply(ctx, [a, b]) invokes immediately with an array of args. bind(ctx, a) returns a new function with this permanently bound — useful for event handlers and partial application.
Architecture level
Architecture
Q
How would you design a scalable event system for a large SPA?
Use the Observer pattern with namespaced events. Key design choices: (1) use a Map<string, Set<Function>> for O(1) lookup and deduplication; (2) return an unsubscribe function from on() to prevent memory leaks; (3) support wildcards or hierarchical events (user:*); (4) add error boundaries so one bad subscriber doesn't break others; (5) consider a BehaviorSubject (RxJS) or signals for reactive state vs. one-time events.
Q
Explain how you'd implement schema validation at the API boundary.
Use a schema library like Zod — define the schema once, get TypeScript types for free, and validate at runtime. Place validation in middleware before business logic. Structure: (1) Define schema → (2) Validate request body → (3) Return structured 400 errors on failure → (4) Pass typed data to handler. For API versioning, maintain separate schemas (v1Schema, v2Schema) and use schemaDiff() in CI to detect breaking changes automatically.
Q
How does garbage collection work in V8 and what causes memory leaks?
V8 uses generational GC: most objects die young and are collected by the Minor GC (Scavenger) in the "new space". Long-lived objects are promoted to "old space" and collected by the Major GC (Mark-Sweep/Mark-Compact). Common memory leaks: (1) forgotten event listeners (element.addEventListener without removeEventListener); (2) closures capturing large objects; (3) global variables; (4) timers (setInterval) referencing removed DOM; (5) detached DOM nodes still referenced in JS. Use Chrome DevTools Heap Snapshot to diagnose.
Q
When would you use a Proxy over a class? Explain with a real system.
A Proxy intercepts object operations (get, set, delete, apply) transparently — the caller doesn't know a proxy is there. Use cases: reactivity (Vue 3 — track all property reads/writes to trigger re-renders), validation (throw on invalid property sets), logging/tracing (log every method call in production), lazy loading (fetch data only on first access), immutability (deep-freeze by throwing on set). Classes are better when you control the API surface; Proxy is better when wrapping external objects you don't own.
