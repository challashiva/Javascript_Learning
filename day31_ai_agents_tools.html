Core Concepts

🔧 What is Tool Calling?

Instead of generating text, the LLM can signal "I need to call a function" by outputting a structured tool_use block with a function name and arguments. Your code executes the function, returns the result, and the LLM continues — grounding its answer in real data.

🔄 The ReAct Loop

Reason + Act: the agent thinks about what it needs, calls a tool, observes the result, reasons again, and repeats until the task is done. Each iteration adds a tool_use and tool_result pair to the message history. The loop ends when the LLM produces a final text response with no more tool calls.

📋 Function Definitions

Each tool is described with a name, description, and JSON Schema for its parameters. The description is critical — the LLM decides when to call a tool based purely on your description. Be specific: "Search ShopCo products by keyword" is better than "search".

🏗️ Structured Output

Use generateObject with a Zod schema to force the LLM to return typed JSON. Perfect for extracting product comparisons, order summaries, or analysis reports. Unlike tool calling, structured output is for the final response — not mid-task actions.

⚡ Parallel vs Sequential

When the LLM needs two independent pieces of data, it can request multiple tool calls in a single turn. Execute them in parallel with Promise.all for speed. Sequential calls are needed when each step depends on the previous result (e.g. search → get details → check stock).

🛡️ Safety & Guardrails

Agents are powerful — and can go wrong. Always set maxSteps to prevent infinite loops, distinguish read-only tools (safe to auto-execute) from write tools (require confirmation), log every tool call, and add a human-in-the-loop gate before irreversible actions like placing orders.

Tool Calling with Vercel AI SDK

app/api/agent/route.ts — defining ShopCo tools
import { streamText, tool } from 'ai'
import { openai } from '@ai-sdk/openai'
import { z } from 'zod'
import { prisma } from '@/lib/prisma'
import { searchProducts } from '@/lib/embeddings'

export async function POST(req: Request) {
  const { messages } = await req.json()

  const result = await streamText({
    model: openai('gpt-4o'),
    maxSteps: 5, // prevent infinite loops
    system: `You are ShopCo's shopping assistant.
Use tools to find real product data. Never guess prices or stock.
Always call searchProducts before recommending anything.`,
    messages,
    tools: {
      // Tool 1: Semantic product search (from Day 30)
      searchProducts: tool({
        description: 'Search ShopCo products by meaning/intent. Use for any product query.',
        parameters: z.object({
          query: z.string().describe('Natural language search query'),
          limit: z.number().optional().default(5),
        }),
        execute: async ({ query, limit }) => {
          return await searchProducts(query, limit)
        },
      }),
      // Tool 2: Check real-time stock
      checkInventory: tool({
        description: 'Check if a specific product is in stock and how many remain.',
        parameters: z.object({
          productId: z.string().describe('The product ID to check'),
        }),
        execute: async ({ productId }) => {
          const inv = await prisma.inventory.findUnique({ where: { productId } })
          return { inStock: (inv?.quantity ?? 0) > 0, quantity: inv?.quantity ?? 0 }
        },
      }),
      // Tool 3: Get product reviews
      getReviews: tool({
        description: 'Get customer reviews for a product to assess quality.',
        parameters: z.object({
          productId: z.string(),
          limit: z.number().optional().default(3),
        }),
        execute: async ({ productId, limit }) => {
          return await prisma.review.findMany({
            where: { productId }, take: limit,
            orderBy: { createdAt: 'desc' },
            select: { rating: true, comment: true, verified: true }
          })
        },
      }),
      // Tool 4: Add to cart (WRITE — confirm before calling in production)
      addToCart: tool({
        description: 'Add a product to the user cart. Only call after explicit user confirmation.',
        parameters: z.object({
          productId: z.string(),
          quantity: z.number().min(1),
        }),
        execute: async ({ productId, quantity }) => {
          // ... cart logic
          return { success: true, message: `Added ${quantity}x to cart` }
        },
      }),
    },
  })
  return result.toDataStreamResponse()
}
Structured output with generateObject — product comparison report
import { generateObject } from 'ai'
import { openai } from '@ai-sdk/openai'
import { z } from 'zod'

const ComparisonSchema = z.object({
  winner:     z.string().describe('Product ID of the recommended choice'),
  summary:    z.string().describe('One sentence recommendation'),
  scores:     z.array(z.object({
    productId:    z.string(),
    valueScore:   z.number().min(1).max(10),
    qualityScore: z.number().min(1).max(10),
    pros:         z.array(z.string()),
    cons:         z.array(z.string()),
  })),
})

export async function compareProducts(products: Product[]) {
  const { object } = await generateObject({
    model: openai('gpt-4o-mini'),
    schema: ComparisonSchema,
    prompt: `Compare these ShopCo products and recommend the best one:
${JSON.stringify(products, null, 2)}`,
  })
  return object // fully typed: ComparisonSchema
}

Frontend: useChat hook wired to the agent route
'use client'
import { useChat } from 'ai/react'

export function ShopCoAgent() {
  const { messages, input, handleInputChange, handleSubmit, isLoading }
    = useChat({ api: '/api/agent' })

  return (
    <div className="agent-chat">
      <div className="messages">
        {messages.map(m => (
          <div key={m.id} className={`msg msg-${m.role}`}>
            {/* Show tool invocations in the UI */}
            {m.toolInvocations?.map(t => (
              <div key={t.toolCallId} className="tool-call">
                <span>🔧 {t.toolName}</span>
                {t.state === 'result' && <span>✓</span>}
              </div>
            ))}
            <p>{m.content}</p>
          </div>
        ))}
      </div>
      <form onSubmit={handleSubmit}>
        <input value={input} onChange={handleInputChange}
          placeholder="Find me trail running shoes under $200..." />
        <button disabled={isLoading}>Send</button>
      </form>
    </div>
  )
}
⚠ Agent Safety Rules for ShopCo:
Always set maxSteps: 5 — without it, a confused agent loops forever and burns tokens. Never auto-execute cart or order tools without user confirmation. Log every tool call to a database for auditing. Return tool_result errors gracefully (don't throw) so the agent can recover. Rate-limit agent endpoints separately from regular API routes.

Interview Q&A

1. What is the difference between tool calling and function calling?
They're the same concept with different names. OpenAI originally called it "function calling", then unified the terminology to "tool calling" in later API versions. Anthropic calls them "tool use". The Vercel AI SDK uses "tools" uniformly. The core mechanic is identical: the LLM outputs a structured request to call a named function with typed arguments, you execute it, and return the result for the LLM to continue.
2. How does the LLM decide which tool to call?
Purely based on your tool's description and parameter descriptions. The model is trained to match user intent against tool descriptions. A description like "Search ShopCo products by semantic similarity — use for any product discovery query" is far better than "search". The model also considers parameter names and their descriptions to extract the right values from user messages. Never rely on the function name alone — write descriptions as if explaining to a new team member.
3. What is maxSteps and why is it critical for agents?
maxSteps caps how many times the agent can go through the reason-act loop before being forcibly stopped. Without it, a confused agent can loop indefinitely (e.g. keeps searching for a product that doesn't exist), burning tokens and money. Set it conservatively (3–5 for simple tasks, 10–15 for complex ones). When maxSteps is hit, either return a partial result with a "couldn't complete" message, or surface the error to the user for manual intervention.
4. When would you use generateObject instead of tool calling?
generateObject is for when you want the final LLM output to be structured JSON (e.g. a product comparison, a sentiment analysis, an order summary). Tool calling is for when the LLM needs to fetch data mid-task before it can answer. Use generateObject for: data extraction, classification, report generation. Use tool calling for: tasks requiring real-time data, multi-step workflows, or side effects like adding to a cart.
5. How do you implement human-in-the-loop for dangerous agent actions?
For irreversible actions (place order, charge card), use a two-phase approach: (1) define a confirmOrder tool that returns a preview without executing — the LLM calls this first and presents it to the user; (2) only execute the real action when the user explicitly confirms. In the Vercel AI SDK, mark write tools as requiring confirmation by returning a confirmation_required flag in the tool result, then check for it in the frontend before proceeding.
6. What is the ReAct pattern and how does it differ from a basic chatbot?
ReAct (Reason + Act) is an agent architecture where the LLM alternates between reasoning (thinking about what it needs) and acting (calling tools). A basic chatbot just generates text from conversation history. A ReAct agent dynamically fetches information, takes actions, and adjusts its plan based on tool results — it can complete tasks that require multiple steps and real-world data. The message history grows with each tool call+result pair, giving the agent memory of what it's already done.
7. How do you handle tool errors in a production agent?
Never throw errors from tool execute functions — catch them and return a structured error object like { error: "Product not found", code: "NOT_FOUND" }. This lets the LLM reason about the failure and adapt (try a different search, tell the user, or skip to the next step). Log all errors with the full tool call context. Set up alerts for high error rates. For transient errors (network timeout, rate limit), implement retry logic inside the execute function with exponential backoff before returning an error.
8. What is the difference between streaming and non-streaming agents?
Non-streaming (generateText): the entire agent loop completes server-side, then the final answer is returned — simpler but the user sees nothing until done. Streaming (streamText): intermediate text, tool call notifications, and the final answer stream to the client in real time — better UX for long-running agents. The Vercel AI SDK's useChat hook handles streaming automatically; toolInvocations on messages let you display tool call progress in the UI.
9. How do you test agents reliably?
Three layers: (1) Unit test tools in isolation — test searchProducts() with known inputs, independent of the LLM. (2) Integration test the agent loop with a mock LLM that always returns predetermined tool calls — test that your executor, error handling, and maxSteps logic work correctly. (3) Evals — run the full agent with the real LLM against a golden dataset of user queries, and assert on the final output (did it recommend an in-stock product? did it stay within budget?). Tools: Vitest for unit/integration, LangSmith or custom scripts for evals.
10. How would you build a multi-agent system for ShopCo?
Orchestrate specialised agents: a Router Agent classifies the intent and delegates to specialists; a Search Agent uses RAG + tool calling to find products; a Review Agent analyses sentiment and summarises reviews; an Order Agent handles cart and checkout (with strict human-in-the-loop). Agents communicate via shared message history or a central state object. Use generateText with tool calling for each sub-agent, with the orchestrator passing context. Key challenge: prevent context explosion — summarise sub-agent results before passing upstream.
