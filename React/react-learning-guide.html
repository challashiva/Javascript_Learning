Quick JS Refresher — Patterns React Uses Constantly

// ── DESTRUCTURING ─────────────────────────────────────────────
const user = { name: 'Alice', age: 30, role: 'admin' };

// Object destructuring (you'll do this with props constantly)
const { name, age } = user;

// With rename and default
const { role = 'user', name: displayName } = user;

// Array destructuring (essential for useState!)
const [first, second, ...rest] = [1, 2, 3, 4];

// ── SPREAD OPERATOR ───────────────────────────────────────────
// Creating new objects without mutating (critical in React!)
const updatedUser = { ...user, age: 31 };         // new object
const newItems = [...existingItems, newItem];      // new array

// ── ARRAY METHODS ─────────────────────────────────────────────
const products = [
  { id: 1, name: 'Laptop', price: 999, inStock: true },
  { id: 2, name: 'Phone',  price: 699, inStock: false },
  { id: 3, name: 'Tablet', price: 499, inStock: true },
];

// map → transforms (use this to render lists in JSX)
const names = products.map(p => p.name);

// filter → subset (remove items without mutating)
const available = products.filter(p => p.inStock);

// reduce → aggregate (totals, grouping, etc.)
const total = products.reduce((sum, p) => sum + p.price, 0);

    return data;
  } catch (error) {
    console.error('Failed to fetch:', error);
    throw error;
  }
}

The JavaScript → React Mindset Shift

The mental models that separate frustrated beginners from confident React developers.

React is not just JavaScript with extra syntax. It's a fundamentally different way of thinking about UI. This mindset shift is where most beginners struggle — master it early.

Key Differences

Vanilla JavaScript React
You imperatively manipulate the DOM You declaratively describe what UI should look like
document.getElementById('btn').innerText = 'Clicked' <Button label={isClicked ? 'Clicked' : 'Click me'} />
You track state manually in variables React tracks state and re-renders automatically
UI is built by mutating the DOM UI is a function of state: UI = f(state)
One big HTML file with scattered JS Small, reusable, composable components
Direct DOM manipulation is normal Direct DOM manipulation is almost always a code smell

The Core Mental Model: UI = f(state)

In React, your UI is a pure function of your data (state). When state changes, React re-runs that function and updates only what changed in the DOM. You never say "update this button's text" — you say "here's my state, derive the UI."

❌ Imperative (Vanilla JS)
// You describe HOW to change things
let count = 0;

document.getElementById('btn')
  .addEventListener('click', () => {
    count++;
    document.getElementById('count')
      .innerText = count;
    if (count > 10) {
      document.getElementById('warn')
        .style.display = 'block';
    }
  });
✅ Declarative (React)
// You describe WHAT it should look like
function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>{count}</p>
      {count > 10 && <Warning />}
      <button onClick={() => setCount(c => c + 1)}>
        Click
      </button>
    </div>
  );
}
⚠️ Critical Mindset Rules
1. Never mutate state directly — always use the setter function.
2. React components are just functions — they take props and return JSX.
3. Think in components — every piece of UI is a self-contained unit.
4. Data flows down, events flow up — props go parent → child, callbacks go child → parent.

Understanding JSX

JSX is not HTML. It's a syntax extension for JavaScript that looks like HTML but compiles to JavaScript function calls. Babel/Vite transforms it behind the scenes.

JSXExplained.jsx JSX 
// What you write:
const element = <h1 className="title">Hello, World!</h1>;

// What it compiles to (React.createElement):
const element = React.createElement(
  'h1',
  { className: 'title' },
  'Hello, World!'
);

// ── JSX RULES ─────────────────────────────────────────────────

// Rule 1: Use className instead of class
<div className="container"></div>

// Rule 2: All tags must be closed (self-closing OK)
<img src="photo.jpg" alt="photo" />
<br />
<input type="text" />

// Rule 3: Return ONE root element — use a Fragment if needed
return (
  <>           {/* React.Fragment shorthand */}
    <h1>Title</h1>
    <p>Content</p>
  </>
);

// Rule 4: JavaScript expressions go inside curly braces
const name = 'Alice';
const num = 42;
return <p>Hello {name}, the answer is {num * 2}</p>;

// Rule 5: Event names are camelCase
<button onClick={handleClick}>Click me</button>

// Rule 6: Style is an object (camelCase properties)
<div style={{ backgroundColor: 'blue', fontSize: '16px' }}></div>

// Rule 7: Comments inside JSX use {/* */}
return (
  <div>
    {/* This is a JSX comment */}
    <p>Content</p>
  </div>
);

Components

The fundamental building blocks of every React application.

A React component is a JavaScript function that returns JSX. Think of components as custom HTML elements — reusable, self-contained, and composable. Everything in React is a component.

Anatomy of a Component

UserCard.jsx JSX 
import React from 'react';

// ① Function name starts with UPPERCASE (required for React to treat it as a component)
function UserCard({ name, role, avatarUrl, isOnline }) {
  // ② Can contain any JavaScript logic above the return
  const initials = name.split(' ').map(n => n[0]).join('');
  const statusColor = isOnline ? '#22c55e' : '#9ca3af';

  // ③ Returns JSX (your UI description)
  return (
    <div className="user-card">
      <div className="avatar">
        {avatarUrl
          ? <img src={avatarUrl} alt={name} />
          : <span>{initials}</span>
        }
        <span
          className="status-dot"
          style={{ backgroundColor: statusColor }}
        />
      </div>
      <div className="info">
        <h3>{name}</h3>
        <p>{role}</p>
      </div>
    </div>
  );
}

// ④ Export for use in other files
export default UserCard;

// ── USAGE ─────────────────────────────────────────────────────
function App() {
  return (
    <div>
      <UserCard
        name="Alice Johnson"
        role="Senior Engineer"
        isOnline={true}
      />
      <UserCard
        name="Bob Smith"
        role="Designer"
        isOnline={false}
      />
    </div>
  );
}

Component Composition

React's power comes from composing small components into larger ones. Think in a tree structure — complex UIs are just trees of simple components.

CompositionExample.jsx JSX 
// Small, focused components
function Badge({ label, variant = 'default' }) {
  return <span className={`badge badge--${variant}`}>{label}</span>;
}

function Avatar({ src, name, size = 'md' }) {
  return (
    <img
      src={src || '/default-avatar.png'}
      alt={name}
      className={`avatar avatar--${size}`}
    />
  );
}

// Composed into a larger component
function TeamMember({ user }) {
  return (
    <div className="team-member">
      <Avatar src={user.avatar} name={user.name} />
      <div>
        <h4>{user.name}</h4>
        <Badge label={user.role} variant="primary" />
      </div>
    </div>
  );
}

// children prop — allows wrapping components
function Card({ title, children }) {
  return (
    <div className="card">
      <h2>{title}</h2>
      <div className="card__body">{children}</div>
    </div>
  );
}

// Usage — Card wraps any content via children
<Card title="Team">
  <TeamMember user={alice} />
  <TeamMember user={bob} />
</Card>

Props

How data flows from parent to child — the backbone of component communication.

Props (properties) are how you pass data into a component. They're read-only — a component should never modify its own props. Think of them as function arguments for your UI.

PropsDeepDive.jsx JSX 
// ── BASIC PROPS ───────────────────────────────────────────────
function Button({ label, onClick, variant = 'primary', disabled = false }) {
  return (
    <button
      className={`btn btn--${variant}`}
      onClick={onClick}
      disabled={disabled}
    >
      {label}
    </button>
  );
}

// ── PROP TYPES (all valid ways to pass props) ─────────────────
<Button label="Save" />              // string prop
<Button label={"Save"} />           // expression (same result)
<Button disabled={true} />         // boolean
<Button disabled />               // boolean shorthand (disabled={true})
<Button onClick={() => save()} />  // function prop
<Button count={42} />              // number
<Button data={[1,2,3]} />          // array
<Button user={{ name: 'Alice' }} /> // object

// ── SPREADING PROPS ───────────────────────────────────────────
const buttonProps = {
  label: 'Submit',
  variant: 'success',
  onClick: handleSubmit
};
<Button {...buttonProps} />         // equivalent to listing each prop

// ── PROP DRILLING EXAMPLE ─────────────────────────────────────
// Data flows: App → Layout → Sidebar → UserMenu → Avatar
function App() {
  const user = { name: 'Alice', avatar: '/alice.png' };
  return <Layout user={user} />;
}

// ── RENDER PROPS PATTERN (advanced) ──────────────────────────
// Pass a function as a prop to control what gets rendered
function DataList({ items, renderItem }) {
  return (
    <ul>
      {items.map((item, idx) => (
        <li key={item.id ?? idx}>{renderItem(item)}</li>
      ))}
    </ul>
  );
}

// Usage — caller controls the rendering
<DataList
  items={users}
  renderItem={(user) => (
    <span>{user.name} — {user.role}</span>
  )}
/>

State & Events

Making components interactive — the heart of React.

State is data that changes over time and should cause the UI to update. Unlike props (received from outside), state is owned and managed by the component itself. useState is the primary hook for managing state.

StateDeepDive.jsx JSX 
import { useState } from 'react';

// ── BASIC STATE ───────────────────────────────────────────────
function Counter() {
  // useState returns [currentValue, setterFunction]
  const [count, setCount] = useState(0); // 0 is initial value

  return (
    <div>
      <p>Count: {count}</p>
      {/* Functional update: safe when new state depends on old */}
      <button onClick={() => setCount(prev => prev + 1)}>+</button>
      <button onClick={() => setCount(prev => prev - 1)}>-</button>
      <button onClick={() => setCount(0)}>Reset</button>
    </div>
  );
}

// ── OBJECT STATE ──────────────────────────────────────────────
function ProfileForm() {
  const [profile, setProfile] = useState({
    firstName: '',
    lastName: '',
    email: '',
  });

  // CRITICAL: Don't mutate state! Always spread and replace.
  const handleChange = (e) => {
    const { name, value } = e.target;
    setProfile(prev => ({
      ...prev,         // keep all existing fields
      [name]: value    // update only the changed field
    }));
  };

  return (
    <form>
      <input name="firstName" value={profile.firstName} onChange={handleChange} />
      <input name="lastName"  value={profile.lastName}  onChange={handleChange} />
      <input name="email"     value={profile.email}     onChange={handleChange} />
    </form>
  );
}

// ── LIFTING STATE UP ──────────────────────────────────────────
// When siblings need to share state, lift it to their parent
function ShoppingApp() {
  const [cart, setCart] = useState([]);

  const addToCart = (item) => {
    setCart(prev => [...prev, item]);
  };

  const removeFromCart = (id) => {
    setCart(prev => prev.filter(item => item.id !== id));
  };

  return (
    <div>
      {/* ProductList receives addToCart as a callback */}
      <ProductList onAddToCart={addToCart} />
      {/* Cart receives the cart state and remove handler */}
      <Cart items={cart} onRemove={removeFromCart} />
    </div>
  );
}
🚨 Common State Mistakes
Never do this: state.count = 5 — direct mutation won't trigger re-render.
Never do this: setCount(count + 1); setCount(count + 1); — use functional form: setCount(c => c + 1) twice instead.

Lists, Keys & Conditional Rendering

Rendering dynamic data and conditional UI — patterns you'll use in every component.
ListsAndConditionals.jsx JSX 
// ── RENDERING LISTS ───────────────────────────────────────────
function TaskList({ tasks }) {
  return (
    <ul>
      {tasks.map((task) => (
        {/* key must be UNIQUE and STABLE — never use index if items reorder */}
        <TaskItem key={task.id} task={task} />
      ))}
    </ul>
  );
}

// ── WHY KEYS MATTER ───────────────────────────────────────────
// Keys help React identify which items changed, added, or removed.
// Without stable keys, React may re-render items incorrectly.
// ✅ Use unique IDs from your data: key={item.id}
// ❌ Avoid array index: key={index} — causes bugs on delete/reorder

// ── CONDITIONAL RENDERING PATTERNS ───────────────────────────
function StatusDisplay({ status, data, error }) {
  // Pattern 1: if/else (outside JSX)
  if (status === 'loading') {
    return <Spinner />;
  }
  if (status === 'error') {
    return <ErrorMessage message={error} />;
  }

  return (
    <div>
      {/* Pattern 2: && operator — renders right side only if left is truthy */}
      {data.length === 0 && <p>No items found.</p>}

      {/* Pattern 3: Ternary — renders one of two things */}
      {data.length > 0
        ? <DataGrid rows={data} />
        : <EmptyState />
      }

      {/* Pattern 4: Variable — for complex conditions */}
      {(() => {
        switch (data.type) {
          case 'chart':  return <Chart data={data} />;
          case 'table':  return <Table data={data} />;
          default:       return <RawData data={data} />;
        }
      })()}
    </div>
  );
}

// ── GOTCHA: 0 is falsy but renders in JSX! ────────────────────
// ❌ This renders "0" on screen if count is 0:
{count && <p>Items: {count}</p>}

// ✅ Fix: convert to boolean first:
{count > 0 && <p>Items: {count}</p>}
{!!count && <p>Items: {count}</p>}

Forms & Controlled Components

Managing user input the React way.
LoginForm.jsx JSX 
import { useState } from 'react';

function LoginForm({ onSubmit }) {
  const [form, setForm] = useState({ email: '', password: '' });
  const [errors, setErrors] = useState({});
  const [isSubmitting, setIsSubmitting] = useState(false);

  const validate = () => {
    const newErrors = {};
    if (!form.email.includes('@')) newErrors.email = 'Invalid email';
    if (form.password.length < 8) newErrors.password = 'Min 8 characters';
    return newErrors;
  };

  const handleChange = ({ target: { name, value } }) => {
    setForm(prev => ({ ...prev, [name]: value }));
    // Clear error for field as user types
    if (errors[name]) setErrors(prev => ({ ...prev, [name]: '' }));
  };

  const handleSubmit = async (e) => {
    e.preventDefault();          // Prevent browser page reload
    const validationErrors = validate();
    if (Object.keys(validationErrors).length > 0) {
      setErrors(validationErrors);
      return;
    }
    setIsSubmitting(true);
    try {
      await onSubmit(form);
    } finally {
      setIsSubmitting(false);
    }
  };

  return (
    <form onSubmit={handleSubmit}>
      <div>
        <input
          type="email"
          name="email"
          value={form.email}
          onChange={handleChange}
          placeholder="you@example.com"
        />
        {errors.email && <span className="error">{errors.email}</span>}
      </div>
      <div>
        <input
          type="password"
          name="password"
          value={form.password}
          onChange={handleChange}
          placeholder="••••••••"
        />
        {errors.password && <span className="error">{errors.password}</span>}
      </div>
      <button type="submit" disabled={isSubmitting}>
        {isSubmitting ? 'Signing in…' : 'Sign In'}
      </button>
    </form>
  );
}

Core Hooks Deep Dive

useState, useReducer, useRef, useMemo, useCallback — mastered.
🔢

useState

Manages simple values. Returns [state, setter]. Triggers re-render when called.

🔄

useReducer

For complex state logic. Like Redux but local. Action → Reducer → New State.

🔗

useRef

Mutable container that doesn't trigger re-render. Use for DOM refs & timers.

⚡

useMemo

Memoizes expensive computed values. Only recalculates when dependencies change.

📌

useCallback

Memoizes functions. Prevents child re-renders when passing callbacks as props.

🆔

useId

Generates stable unique IDs for accessibility labels across server and client.

HooksDeepDive.jsx JSX 
import { useState, useReducer, useRef, useMemo, useCallback } from 'react';

// ── useReducer — for complex state transitions ─────────────────
const cartReducer = (state, action) => {
  switch (action.type) {
    case 'ADD_ITEM':
      return { ...state, items: [...state.items, action.payload] };
    case 'REMOVE_ITEM':
      return {
        ...state,
        items: state.items.filter(i => i.id !== action.payload)
      };
    case 'CLEAR':
      return { ...state, items: [] };
    default:
      return state;
  }
};

function Cart() {
  const [state, dispatch] = useReducer(cartReducer, { items: [] });

  return (
    <div>
      <p>{state.items.length} items</p>
      <button onClick={() => dispatch({ type: 'ADD_ITEM', payload: newItem })}>
        Add
      </button>
      <button onClick={() => dispatch({ type: 'CLEAR' })}>
        Clear Cart
      </button>
    </div>
  );
}

// ── useRef — mutable container, does not trigger re-render ─────
function StopWatch() {
  const [time, setTime] = useState(0);
  const intervalRef = useRef(null);   // stores timer ID without re-render
  const inputRef = useRef(null);      // direct DOM access

  const start = () => {
    intervalRef.current = setInterval(() => {
      setTime(t => t + 1);
    }, 1000);
  };

  const stop = () => clearInterval(intervalRef.current);

  const focusInput = () => inputRef.current?.focus();

  return (
    <div>
      <p>{time}s</p>
      <button onClick={start}>Start</button>
      <button onClick={stop}>Stop</button>
      <input ref={inputRef} />
      <button onClick={focusInput}>Focus</button>
    </div>
  );
}

// ── useMemo & useCallback — performance optimization ───────────
function FilteredList({ items, onItemClick }) {
  const [query, setQuery] = useState('');

  // useMemo: only recalculate when items or query changes
  const filtered = useMemo(
    () => items.filter(i => i.name.toLowerCase().includes(query.toLowerCase())),
    [items, query]
  );

  // useCallback: stable function reference across renders
  const handleClick = useCallback(
    (item) => onItemClick(item),
    [onItemClick]
  );

  return (
    <div>
      <input value={query} onChange={e => setQuery(e.target.value)} />
      {filtered.map(item => (
        <Item key={item.id} item={item} onClick={handleClick} />
      ))}
    </div>
  );
}

useEffect & the Component Lifecycle

Side effects, data fetching, subscriptions — done right.

useEffect lets you perform side effects (API calls, DOM manipulation, subscriptions, timers) after React renders. Understanding its dependency array is crucial to avoiding bugs.

UseEffectMastery.jsx JSX 
import { useState, useEffect } from 'react';

// ── DEPENDENCY ARRAY PATTERNS ─────────────────────────────────

// 1. No array — runs after EVERY render (usually not what you want)
useEffect(() => { ... });

// 2. Empty array [] — runs ONCE after mount (like componentDidMount)
useEffect(() => { ... }, []);

// 3. With dependencies — runs when any dependency changes
useEffect(() => { ... }, [userId, filter]);

// ── REAL EXAMPLE: Data Fetching ───────────────────────────────
function UserProfile({ userId }) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    // Cleanup: ignore stale responses when userId changes quickly
    let isMounted = true;

    const fetchUser = async () => {
      setLoading(true);
      setError(null);
      try {
        const res = await fetch(`/api/users/${userId}`);
        if (!res.ok) throw new Error('Failed to fetch');
        const data = await res.json();
        if (isMounted) setUser(data); // only update if still mounted
      } catch (err) {
        if (isMounted) setError(err.message);
      } finally {
        if (isMounted) setLoading(false);
      }
    };

    fetchUser();

    // Cleanup function — runs before next effect or unmount
    return () => { isMounted = false; };

  }, [userId]); // Re-run only when userId changes

  if (loading) return <Spinner />;
  if (error)   return <p>Error: {error}</p>;
  if (!user)   return null;

  return <div>{user.name}</div>;
}

// ── EVENT LISTENER CLEANUP ────────────────────────────────────
useEffect(() => {
  const handleResize = () => setWidth(window.innerWidth);
  window.addEventListener('resize', handleResize);
  return () => window.removeEventListener('resize', handleResize);
}, []);
⚠️ useEffect Pitfalls
Missing dependencies cause stale closure bugs. Include everything your effect reads from component scope.
Infinite loops happen when you set state inside an effect without proper dependencies.
Always clean up subscriptions, timers, and event listeners in the return function.

Custom Hooks

Extract and reuse stateful logic across components — the React superpower.

Custom hooks are JavaScript functions starting with "use" that can call other hooks. They let you extract complex, reusable stateful logic out of components — the single biggest step toward professional React code.

hooks/useFetch.js JSX 
import { useState, useEffect, useCallback } from 'react';

// ── CUSTOM HOOK: useFetch ─────────────────────────────────────
// Encapsulates all data-fetching logic in one reusable hook
export function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState(null);

  const execute = useCallback(async () => {
    setLoading(true);
    setError(null);
    try {
      const res = await fetch(url);
      if (!res.ok) throw new Error(`HTTP ${res.status}`);
      setData(await res.json());
    } catch (e) {
      setError(e.message);
    } finally {
      setLoading(false);
    }
  }, [url]);

  useEffect(() => { execute(); }, [execute]);

  return { data, loading, error, refetch: execute };
}

// ── CUSTOM HOOK: useLocalStorage ──────────────────────────────
export function useLocalStorage(key, initialValue) {
  const [value, setValue] = useState(() => {
    try {
      const stored = localStorage.getItem(key);
      return stored ? JSON.parse(stored) : initialValue;
    } catch { return initialValue; }
  });

  const set = useCallback((newValue) => {
    setValue(newValue);
    localStorage.setItem(key, JSON.stringify(newValue));
  }, [key]);

  return [value, set];
}

// ── CUSTOM HOOK: useDebounce ──────────────────────────────────
export function useDebounce(value, delay = 300) {
  const [debounced, setDebounced] = useState(value);

  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(timer);
  }, [value, delay]);

  return debounced;
}

// ── USAGE ─────────────────────────────────────────────────────
function SearchPage() {
  const [query, setQuery] = useState('');
  const debouncedQuery = useDebounce(query, 400);
  const { data, loading } = useFetch(`/api/search?q=${debouncedQuery}`);
  const [recentSearches, setRecentSearches] = useLocalStorage('recent', []);

      <input value={query} onChange={e => setQuery(e.target.value)} />
      {loading ? <Spinner /> : <Results data={data} />}
    </div>
  );
}

import { createContext, useContext, useState, useCallback } from 'react';

// 1. Create the context
const AuthContext = createContext(null);

// 2. Create the Provider component (wraps your app or subtree)
export function AuthProvider({ children }) {
  const [user, setUser] = useState(null);
  const [token, setToken] = useState(localStorage.getItem('token'));

  const login = useCallback(async (credentials) => {
    const { user, token } = await authApi.login(credentials);
    setUser(user);
    setToken(token);
    localStorage.setItem('token', token);
  }, []);

  const logout = useCallback(() => {
    setUser(null);
    setToken(null);
    localStorage.removeItem('token');
  }, []);

  const value = {
    user,
    token,
    login,
    logout,
    isAuthenticated: !!user,
  };

  return (
    <AuthContext.Provider value={value}>
      {children}
    </AuthContext.Provider>
  );
}

// 3. Custom hook for consuming the context (best practice)
export function useAuth() {
  const context = useContext(AuthContext);
  if (!context) {
    throw new Error('useAuth must be used within AuthProvider');
  }
  return context;
}

// 4. Usage anywhere in the tree — no prop drilling!
function Header() {

    <header>
      {isAuthenticated
        ? <button onClick={logout}>Logout ({user.name})</button>
        : <a href="/login">Login</a>
      }
    </header>
  );
}

// Zustand — minimal boilerplate, no providers needed
const useStore = create((set, get) => ({
  // State
  user: null,
  cart: [],
  theme: 'dark',

  // Actions

}));

}

// Components that work together, sharing implicit state via Context.

const TabContext = createContext();

function Tabs({ children, defaultTab }) {
  const [activeTab, setActiveTab] = useState(defaultTab);
  return (
    <TabContext.Provider value={{ activeTab, setActiveTab }}>
      <div className="tabs">{children}</div>
    </TabContext.Provider>
  );
}

Tabs.List = function TabList({ children }) {
  return <div className="tabs__list" role="tablist">{children}</div>;
};

Tabs.Tab = function Tab({ id, children }) {
  const { activeTab, setActiveTab } = useContext(TabContext);
  return (
    <button
      role="tab"
      aria-selected={activeTab === id}
      onClick={() => setActiveTab(id)}
    >
      {children}
    </button>
  );
};

Tabs.Panel = function TabPanel({ id, children }) {
  const { activeTab } = useContext(TabContext);
  return activeTab === id ? <div role="tabpanel">{children}</div> : null;
};

// Clean, readable usage:
<Tabs defaultTab="overview">
  <Tabs.List>
    <Tabs.Tab id="overview">Overview</Tabs.Tab>
    <Tabs.Tab id="details">Details</Tabs.Tab>
  </Tabs.List>
  <Tabs.Panel id="overview">Overview content</Tabs.Panel>
  <Tabs.Panel id="details">Details content</Tabs.Panel>
</Tabs>

// ── ERROR BOUNDARIES ─────────────────────────────────────────
// Catch JS errors in component trees (still class-based in React 18)
class ErrorBoundary extends React.Component {
  state = { hasError: false, error: null };

  static getDerivedStateFromError(error) {
    return { hasError: true, error };
  }

  componentDidCatch(error, info) {
    // Log to error tracking service (Sentry, etc.)
    errorTracker.capture(error, info);
  }

  render() {
    if (this.state.hasError) {
      return this.props.fallback || <p>Something went wrong.</p>;
    }
    return this.props.children;
  }
}

import { render, screen, fireEvent, waitFor } from '@testing-library/react';
import { vi } from 'vitest';
import LoginForm from './LoginForm';

// Test file structure — describe groups, it/test for individual tests
describe('LoginForm', () => {

  it('renders email and password fields', () => {
    render(<LoginForm onSubmit={() => {}} />);

    // Query by accessible role — not by class names!
    expect(screen.getByRole('textbox', { name: /email/i })).toBeInTheDocument();
    expect(screen.getByLabelText(/password/i)).toBeInTheDocument();
  });

  it('shows validation errors for empty submit', async () => {
    render(<LoginForm onSubmit={() => {}} />);

    // Simulate clicking submit without filling form
    fireEvent.click(screen.getByRole('button', { name: /sign in/i }));

    await waitFor(() => {
      expect(screen.getByText(/invalid email/i)).toBeInTheDocument();
      expect(screen.getByText(/min 8 characters/i)).toBeInTheDocument();
    });
  });

  it('calls onSubmit with credentials on valid submit', async () => {
    const mockSubmit = vi.fn().mockResolvedValue({ success: true });
    render(<LoginForm onSubmit={mockSubmit} />);

    // Type into fields
    fireEvent.change(screen.getByLabelText(/email/i), {
      target: { value: 'user@example.com' }
    });
    fireEvent.change(screen.getByLabelText(/password/i), {
      target: { value: 'securepass123' }
    });
    fireEvent.click(screen.getByRole('button', { name: /sign in/i }));

    await waitFor(() => {
      expect(mockSubmit).toHaveBeenCalledWith({
        email: 'user@example.com',
        password: 'securepass123'
      });
    });
  });
});
💡 Testing Philosophy
Test behavior, not implementation. Ask: "What would a user do?" Query by text, role, and labels — not by CSS classes or component internals. Your tests should remain valid even if you refactor the component completely.

Best Practices Checklist

  • One component per file — makes imports, testing, and git diffs clean
  • Co-locate tests — Button.jsx and Button.test.jsx in the same folder
  • Barrel exports — index.js in each folder for clean imports
  • Separate concerns — UI logic in components, business logic in hooks/utils
  • TypeScript — adopt it from day one in any production project
  • Absolute imports — configure path aliases to avoid ../../../ hell
  • Consistent naming — PascalCase for components, camelCase for hooks and utils
  • Error boundaries — wrap routes and async sections to prevent full-page crashes
  • Environment variables — never hardcode API keys or secrets
  • Lint + format — ESLint with eslint-plugin-react-hooks + Prettier
