Variables & Data Types
var · let · const · primitives · type coercion
+

📖 Definition

Variables are named containers that store data. JavaScript has 8 data types: string, number, boolean, null, undefined, BigInt, Symbol, and object.

⚡ Why It Matters

Everything in JavaScript is stored as data. Understanding types prevents unexpected bugs caused by JavaScript's automatic type conversion (coercion).

🌍 Real-World Use Cases

  • Storing user input from forms
  • Tracking state like cart items, scores, or toggle states
  • Checking conditions (boolean flags)
// Simple Example
// Three ways to declare variables
var oldWay = "avoid using this";   // function-scoped, hoisted, legacy
let count = 0;                   // block-scoped, can be reassigned
const PI = 3.14159;              // block-scoped, cannot be reassigned

// Primitive data types
const name = "Alice";            // string
const age = 30;                  // number
const isLoggedIn = true;         // boolean
const score = null;              // null (intentional empty)
let result;                      // undefined (not yet assigned)

// Type checking
console.log(typeof name);        // "string"
console.log(typeof age);         // "number"
console.log(typeof null);        // "object" ← famous JS bug!
// Advanced: Type Coercion Gotchas
// JavaScript auto-converts types — this surprises everyone!
console.log(1 + "2");     // "12" (number → string)
console.log("5" - 2);     // 3   (string → number)
console.log(true + 1);    // 2   (true = 1)
console.log("" == false); // true (loose equality)
console.log("" === false);// false (strict equality ← ALWAYS use this)

// Explicit conversion (best practice)
Number("42")      // 42
String(42)        // "42"
Boolean(0)       // false
Boolean("hello") // true

// Falsy values (be aware!)
// false, 0, "", null, undefined, NaN → all falsy

⚠️ Common Mistakes

  • Using == instead of === — always use strict equality
  • Using var — use let or const instead
  • Not understanding that const for objects/arrays still allows mutation of contents
  • Forgetting typeof null === "object" is a known JS bug

❓ Interview Q&A

What is the difference between let, const, and var?▶
var is function-scoped and hoisted (can be used before declaration). let is block-scoped, can be reassigned. const is block-scoped and cannot be reassigned (but object/array contents can still change). Prefer const by default, use let when you need reassignment, never use var.
What is the difference between == and ===?▶
== (loose equality) converts types before comparing. === (strict equality) checks both value AND type. Example: 0 == false is true but 0 === false is false. Always use ===.
What is NaN and how do you check for it?▶
NaN stands for "Not a Number" — result of invalid math like "abc" * 2. The tricky part: NaN === NaN is false! Use Number.isNaN(value) to properly check for it.

Functions
declarations · expressions · arrow functions · HOF · IIFE
+

📖 Definition

Functions are reusable blocks of code that take inputs (parameters), perform actions, and return outputs. They are first-class citizens in JS — they can be stored in variables, passed as arguments, and returned from other functions.

⚡ Why It Matters

Functions are the building blocks of every JavaScript app. Understanding function types, hoisting, and this binding is critical for avoiding bugs and writing clean code.

// All function types
// 1. Function Declaration — hoisted to top of scope
function greet(name) {
  return `Hello, ${name}!`;
}

// 2. Function Expression — NOT hoisted
const greet2 = function(name) {
  return `Hello, ${name}!`;
};

// 3. Arrow Function — concise syntax, no own 'this'
const greet3 = (name) => `Hello, ${name}!`;
const double = n => n * 2;           // single param: no parens needed
const add = (a, b) => a + b;          // single expression: implicit return

// 4. Default Parameters
const createUser = (name, role = "viewer") => ({ name, role });

// 5. Rest Parameters & Spread
const sum = (...nums) => nums.reduce((a, b) => a + b, 0);
sum(1, 2, 3, 4);  // 10

// 6. IIFE — Immediately Invoked Function Expression
(function() {
  const private = "This won't pollute global scope";
})();
// Higher-Order Functions (HOF)
// Functions that take or return other functions
const numbers = [1, 2, 3, 4, 5];

numbers.map(n => n * 2);           // [2, 4, 6, 8, 10]
numbers.filter(n => n % 2 === 0); // [2, 4]
numbers.reduce((acc, n) => acc + n, 0); // 15

// Custom HOF: function that returns a function
const multiply = (factor) => (num) => num * factor;
const triple = multiply(3);
triple(5); // 15

⚠️ Common Mistakes

  • Arrow functions don't have their own this — don't use them as object methods
  • Forgetting that function declarations are hoisted but function expressions are not
  • Forgetting to return in non-arrow functions

❓ Interview Q&A

What is the difference between arrow functions and regular functions?▶
Arrow functions: (1) don't have their own this — they inherit this from surrounding scope, (2) can't be used as constructors, (3) don't have arguments object, (4) are always anonymous. Regular functions: bind their own this dynamically based on how they're called.
What is function hoisting?▶
Function declarations are moved to the top of their scope during the compilation phase. This means you can call a function before it's defined in code. Function expressions and arrow functions assigned to variables are NOT hoisted (only the variable declaration is).

❓ Interview Q&A

What is the difference between slice and splice?▶
slice(start, end) returns a new array — does NOT modify the original. splice(start, deleteCount, ...items) modifies the original array and returns removed elements. In React, always prefer slice to maintain immutability.
What is the difference between shallow copy and deep copy?▶
Shallow copy (spread {...obj}, Object.assign) copies only top-level properties. Nested objects still share references. Deep copy (structuredClone(obj) or JSON.parse(JSON.stringify(obj))) recursively copies everything. Use deep copy when you have nested objects you don't want shared.

React Introduction & JSX
what is React · virtual DOM · JSX · rendering

📖 What is React?

React is a JavaScript library for building user interfaces. It creates a Virtual DOM — a lightweight copy of the real DOM — to efficiently update only what changed instead of re-rendering everything.

⚡ Why React?

  • Component-based architecture = reusability
  • Declarative — describe WHAT the UI looks like, not HOW to change it
  • Huge ecosystem, great tooling, industry standard
// JSX — JavaScript + HTML syntax
// JSX is syntactic sugar for React.createElement()
const element = <h1 className="title">Hello World</h1>;

// JSX Rules:
// 1. Always return ONE root element (or use <>...</> fragment)
// 2. Use className (not class), htmlFor (not for)
// 3. All tags must be closed: <img /> not <img>
// 4. JavaScript expressions inside {curly braces}

const App = () => {
  const name = "Alice";
  const isAdmin = true;

  return (
    <>
      <h1>Welcome, {name}!</h1>
      {isAdmin && <span>Admin</span>}  // conditional rendering
      <p>{isAdmin ? "Full access" : "Limited access"}</p>
    </>
  );
};

❓ Interview Q&A

What is the Virtual DOM and why does React use it?▶
The Virtual DOM is an in-memory representation of the real DOM. When state changes, React creates a new Virtual DOM tree and diffs it against the previous one (reconciliation). Only the actual changed elements are updated in the real DOM, making updates fast and efficient.
What is JSX? Is it required in React?▶
JSX is a syntax extension that lets you write HTML-like code in JavaScript. It's compiled by Babel to React.createElement() calls. It's not technically required — you could write raw React.createElement() — but JSX makes code much more readable and is the standard approach.

Closures & Scope
lexical scope · closure · IIFE · private variables · module pattern
+

📖 What is a Closure?

A closure is a function that remembers variables from its outer scope even after that outer function has finished executing. Think of it as a function bundled with its "memory".

// Closures in depth
// Basic Closure
function outer() {
  let count = 0;                    // lives in outer's scope
  return function inner() {
    count++;                          // "closes over" count
    return count;
  };
}
const increment = outer();
increment(); // 1
increment(); // 2
increment(); // 3 — count persists in memory!

// Real-World: Factory function with private state
function createBankAccount(initialBalance) {
  let balance = initialBalance; // PRIVATE — can't be accessed outside
  
  return {
    deposit(amount) { balance += amount; },
    withdraw(amount) {
      if (amount > balance) throw new Error("Insufficient funds");
      balance -= amount;
    },
    getBalance() { return balance; }
  };
}

const account = createBankAccount(100);
account.deposit(50);
account.getBalance(); // 150
account.balance;       // undefined — truly private!

// Closure in loops — classic gotcha
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100); // prints 3, 3, 3 ❌
}

for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100); // prints 0, 1, 2 ✅
}

❓ Interview Q&A

What is a closure and give a practical example?▶
A closure is a function that retains access to its outer scope's variables after the outer function returns. Practical examples: (1) data privacy / private variables, (2) memoization / caching, (3) event handlers that remember context, (4) partial application / currying. In React, every callback inside a component is a closure over state and props.
What is the difference between lexical scope and dynamic scope?▶
JavaScript uses lexical (static) scope — a function's scope is determined by where it's WRITTEN in code, not where it's called. Dynamic scope (used by some other languages) would be determined by the call stack. Closures exist because of lexical scoping.

// Evolution of Async in JavaScript
// STAGE 1: Callbacks — "callback hell"
fetchUser(id, (err, user) => {
  if (err) return console.error(err);
  fetchPosts(user.id, (err, posts) => {  // nested & messy
    if (err) return console.error(err);

      // ... even deeper
    });
  });
});

// STAGE 2: Promises — chainable, better error handling
fetchUser(id)
  .then(user => fetchPosts(user.id))
  .then(posts => fetchComments(posts[0].id))
  .then(comments => console.log(comments))
  .catch(err => console.error("Error:", err))
  .finally(() => console.log("Done!"));

// STAGE 3: async/await — reads like synchronous code ✅
async function loadUserData(id) {
  try {
    const user = await fetchUser(id);
    const posts = await fetchPosts(user.id);
    const comments = await fetchComments(posts[0].id);
    return { user, posts, comments };
  } catch (error) {
    console.error("Failed:", error);
    throw error;
  }
}

// Parallel requests — don't await sequentially if independent!

  fetchUsers(),
  fetchProducts()
]);

// Other Promise utilities

Promise.race([...])        // first one to resolve/reject wins
Promise.any([...])         // first to resolve (ignores rejections)

❓ Interview Q&A

What are the states of a Promise?▶
A Promise has 3 states: (1) Pending — initial state, neither fulfilled nor rejected. (2) Fulfilled — operation completed successfully, .then() is called. (3) Rejected — operation failed, .catch() is called. Once settled (fulfilled or rejected), a Promise cannot change state.
What is the difference between Promise.all and Promise.allSettled?▶
Promise.all rejects immediately if ANY promise rejects (fail-fast). Promise.allSettled waits for ALL promises to complete and returns an array of objects with {status: 'fulfilled'|'rejected', value|reason}. Use allSettled when you need results from all operations even if some fail.

Error Handling & Debugging

// Comprehensive Error Handling
// Custom Error classes
class ApiError extends Error {
  constructor(message, statusCode) {
    super(message);
    this.name = "ApiError";
    this.statusCode = statusCode;
  }
}

// Proper async error handling
async function fetchData(url) {
  try {
    const res = await fetch(url);
    if (!res.ok) throw new ApiError("Request failed", res.status);
    return await res.json();
  } catch (err) {
    if (err instanceof ApiError) {
      console.error(`API Error ${err.statusCode}: ${err.message}`);
    } else {
      console.error("Network error:", err);
    }
    throw err; // re-throw so callers can handle it
  } finally {
    console.log("Request completed"); // ALWAYS runs
  }
}
// React Error Boundary
// Catches errors in component tree (class component required)
class ErrorBoundary extends React.Component {
  state = { hasError: false, error: null };

  static getDerivedStateFromError(error) {
    return { hasError: true, error };
  }

  componentDidCatch(error, info) {
    logToMonitoring(error, info.componentStack); // e.g., Sentry
  }

  render() {
    if (this.state.hasError) {
      return <h2>Something went wrong. <button onClick={() => this.setState({hasError: false})}>Retry</button></h2>;
    }
    return this.props.children;
  }
}

import { useState, useReducer, useMemo, useCallback, useRef, useContext } from 'react';

// useReducer — for complex state logic (like mini-Redux)
const reducer = (state, action) => {
  switch (action.type) {
    case "INCREMENT": return { ...state, count: state.count + 1 };
    case "RESET":     return { count: 0 };
    default: return state;
  }
};
const [state, dispatch] = useReducer(reducer, { count: 0 });
dispatch({ type: "INCREMENT" });

const sortedList = useMemo(
  () => [...items].sort((a, b) => a.price - b.price),
  [items]  // only recalculate when items changes
);

// useCallback — cache functions (for child component optimization)
const handleClick = useCallback(() => {
  setCount(prev => prev + 1);
}, []);  // [] = never recreated

// useRef — mutable value that doesn't trigger re-render
const inputRef = useRef(null);
inputRef.current.focus();  // DOM access

const renderCount = useRef(0);
renderCount.current++;  // track without re-render

// useContext — consume context
const ThemeContext = React.createContext("light");
const theme = useContext(ThemeContext);

⚠️ Common Hook Mistakes

  • Calling hooks inside conditionals or loops — hooks MUST be called at the top level
  • Missing dependencies in useEffect/useMemo dependency arrays
  • Overusing useMemo/useCallback — premature optimization adds complexity
  • Using stale closures — state inside callbacks can be outdated

❓ Interview Q&A

When should you use useReducer vs useState?▶
Use useReducer when: (1) next state depends on previous state in complex ways, (2) you have multiple sub-values in state that change together, (3) you want to co-locate state logic, (4) state transitions need to be testable. Use useState for simple independent values. Rule of thumb: if you have 3+ related state values or complex update logic, switch to useReducer.
What is the difference between useMemo and useCallback?▶
useMemo memoizes a computed value (the result of a function). useCallback memoizes a function itself. You'd use useCallback when passing a callback to a child component wrapped in React.memo, to prevent the child from re-rendering due to a new function reference every render.

const Component = ({ userId }) => {

  useEffect(() => {
    let cancelled = false; // prevent state update after unmount

    const loadUser = async () => {
      const data = await fetchUser(userId);
      if (!cancelled) setUser(data);
    };

    loadUser();

    // Cleanup function — runs before next effect or on unmount
    return () => { cancelled = true; };
  }, [userId]);

  // 4. Event listeners — ALWAYS cleanup!
  useEffect(() => {
    const handleResize = () => console.log(window.innerWidth);
    window.addEventListener("resize", handleResize);
    return () => window.removeEventListener("resize", handleResize);
  }, []);

  // 5. Timers — ALWAYS cleanup!
  useEffect(() => {
    const id = setInterval(() => tick(), 1000);
    return () => clearInterval(id);
  }, []);

  return <div>{user?.name}</div>;
};

📖 How JavaScript Actually Works

JavaScript is single-threaded — it can only do one thing at a time. The Event Loop manages asynchronous operations. The Call Stack executes code. The Web APIs handle async tasks (timers, fetch). Completed callbacks go to the Task Queue. The Event Loop moves tasks from the queue to the stack when the stack is empty.

// Event Loop Order — predict the output!

setTimeout(() => {
  console.log("2 - setTimeout");      // macrotask queue
}, 0);

Promise.resolve().then(() => {
  console.log("3 - Promise");          // microtask queue
});

queueMicrotask(() => {
  console.log("4 - queueMicrotask");   // microtask queue
});

console.log("5 - End");              // synchronous

// Output order: 1, 5, 3, 4, 2
// WHY: Sync first → Microtasks (Promises) → Macrotasks (setTimeout)

// Blocking the event loop — BAD practice
const heavyWork = () => {
  for (let i = 0; i < 1_000_000_000; i++) {} // ← freezes the UI!
};

❓ Interview Q&A

What is the difference between microtasks and macrotasks?▶
Microtasks (Promise callbacks, queueMicrotask, MutationObserver) run after the current task completes but BEFORE the next macrotask. Macrotasks (setTimeout, setInterval, I/O callbacks) are processed one per event loop iteration. The engine drains the entire microtask queue before moving to the next macrotask.
How would you avoid blocking the event loop with heavy computation?▶
Options: (1) Web Workers — run code in a separate thread. (2) Chunking — break work into pieces with setTimeout(fn, 0) between each. (3) requestIdleCallback — run during browser idle periods. (4) Move computation to the server. The key is never running synchronous loops that take longer than ~16ms (one frame).

    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key);
    const result = fn(...args);
    cache.set(key, result);

// { a: 3, b: 2, c: 1 }

// Binary Search — O(log n)
function binarySearch(arr, target) {
  let left = 0, right = arr.length - 1;
  while (left <= right) {
    const mid = Math.floor((left + right) / 2);
    if (arr[mid] === target) return mid;
    else if (arr[mid] < target) left = mid + 1;
    else right = mid - 1;
  }
  return -1;
}

// Two-Pointer — classic pattern for sorted arrays
function twoSum(nums, target) {
  let left = 0, right = nums.length - 1;
  while (left < right) {
    const sum = nums[left] + nums[right];
    if (sum === target) return [left, right];
    else if (sum < target) left++;
    else right--;
  }
}

// Sliding Window — O(n) instead of O(n²)
function maxSumSubarray(arr, k) {
  let sum = arr.slice(0, k).reduce((a, b) => a + b, 0);
  let max = sum;
  for (let i = k; i < arr.length; i++) {
    sum += arr[i] - arr[i - k];
    max = Math.max(max, sum);
  }
  return max;
}

❓ Interview Q&A

When does a React component re-render?▶
A component re-renders when: (1) its state changes, (2) its props change, (3) its parent re-renders (even if props didn't change!), (4) context it consumes changes. Use React.memo to prevent re-renders when props haven't changed. Note: React.memo is a shallow comparison by default.
What is reconciliation in React?▶
Reconciliation is React's diffing algorithm that determines the minimum DOM changes needed. React compares the new Virtual DOM tree with the previous one. It uses the component type and key prop to identify which elements have changed. Same type = update props. Different type = destroy and create. Keys help React match list items across renders.

// useLocalStorage — persists state in localStorage
function useLocalStorage(key, initialValue) {
  const [value, setValue] = useState(() => {
    try {
      const stored = localStorage.getItem(key);
      return stored ? JSON.parse(stored) : initialValue;
    } catch { return initialValue; }
  });

  const set = useCallback((val) => {
    setValue(val);
    localStorage.setItem(key, JSON.stringify(val));
  }, [key]);

  return [value, set];
}

// useDebounce — debounces a value
function useDebounce(value, delay = 300) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const t = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(t);
  }, [value, delay]);
  return debounced;
}

// useFetch — reusable data fetching
function useFetch(url) {
  const [state, dispatch] = useReducer(
    (s, a) => ({ ...s, ...a }),
    { data: null, loading: true, error: null }
  );

  useEffect(() => {
    if (!url) return;
    let active = true;
    dispatch({ loading: true, error: null });
    fetch(url)
      .then(r => r.json())
      .then(data => active && dispatch({ data, loading: false }))
      .catch(error => active && dispatch({ error: error.message, loading: false }));
    return () => { active = false; };
  }, [url]);

  return state;
}

Master Interview Q&A
Top 30 most-asked JavaScript & React interview questions
+

🔥 JavaScript — Senior Level

Explain the prototype chain.▶
Every JavaScript object has an internal [[Prototype]] property pointing to another object. When you access a property, JS first looks at the object itself, then walks up the chain through prototypes until it finds it or reaches null. This is how inheritance works. Object.prototype is at the top of the chain.
What is the difference between call, apply, and bind?▶
All three set the this context. call(ctx, arg1, arg2) invokes immediately with individual args. apply(ctx, [arg1, arg2]) invokes immediately with array of args. bind(ctx, arg1) returns a NEW function with this permanently set, useful for event handlers.
What is hoisting?▶
Variable and function declarations are moved to the top of their scope during compilation. var declarations are hoisted AND initialized as undefined. let/const are hoisted but NOT initialized — accessing them before declaration causes a ReferenceError (the "Temporal Dead Zone"). Function declarations are fully hoisted (name + body).
What are WeakMap and WeakSet used for?▶
WeakMap/WeakSet hold "weak" references — if the key (object) has no other references, it can be garbage collected. Regular Map/Set would prevent GC. Use cases: caching computed values without memory leaks, storing private data for class instances, tracking DOM nodes that may be removed.
Explain generators and iterators.▶
An iterator is any object with a next() method returning {value, done}. A generator is a function that produces an iterator using function* and yield. Generators are lazy — they only compute values when requested. Use cases: infinite sequences, async iteration, implementing data pipelines.

⚛️ React — Senior Level

What is the rules of hooks and why do they exist?▶
Two rules: (1) Only call hooks at the top level — not inside conditionals, loops, or nested functions. (2) Only call hooks from React functions. WHY: React relies on the ORDER of hook calls to track state between renders. If you call hooks conditionally, the order can change across renders, breaking React's ability to associate state with the right hook.
How does React handle updates? What is batching?▶
React groups multiple state updates into a single re-render for performance. In React 18, ALL updates are batched by default (including inside setTimeout, Promises, event handlers). Previously, only updates inside React event handlers were batched. Use flushSync if you need to force an immediate synchronous update.
What is the difference between controlled and uncontrolled components?▶
Controlled: form value is controlled by React state. React is the single source of truth. Requires value + onChange. Uncontrolled: DOM is the source of truth. Access values via ref. Controlled components give you more control and validation. Uncontrolled are simpler for file inputs or integrating non-React libraries.
What is the Context API and when NOT to use it?▶
Context provides a way to pass data through the component tree without prop drilling. BUT: any component consuming context re-renders whenever the context value changes, even if they only use a small part of it. Don't use context for frequently-changing state (e.g., mouse position, animation values) — it will cause excessive re-renders. Use Zustand or Redux for that.
What is React.StrictMode and what does it do?▶
A tool for catching potential issues. In development only (not production), it: (1) double-invokes components to detect side effects in render, (2) double-invokes effects to detect missing cleanups, (3) warns about deprecated APIs. This is why effects run twice in dev — it's intentional to surface bugs.
