01 How SPA routing works — the browser History API foundation
traditional MPA
Every URL = a server request
In a classic multi-page app, clicking a link causes the browser to send an HTTP request, the server returns a new HTML page, and the browser replaces everything — full reload, white flash, lost scroll position. Every page transition is a round trip to the server.
SPA routing
URL changes without a server request
React Router uses the browser's History API — window.history.pushState() — to change the URL bar without triggering a page load. React then looks at the current URL and renders the matching component. The server only serves one HTML file; all routing happens in JavaScript.
benefits
Instant navigation, shared state
Because the page never fully reloads, state (auth tokens, cached data, scroll position) can be preserved across navigation. Transitions feel instant. The user never sees a blank white screen between pages. React Router intercepts <a> clicks, updates the URL, and swaps the rendered component.
server config note
The server must serve index.html for all routes
Since the server only has index.html, if a user navigates directly to /dashboard, the server must return index.html (not 404). Vite handles this in dev mode automatically. In production (Vercel, Netlify) you configure a rewrite rule: all paths → index.html.
What happens when you click a React Router Link
① Click
User clicks a <Link to="/about"> component.
② preventDefault
React Router calls e.preventDefault() — the browser's default navigation (page reload) is stopped.
③ pushState
window.history.pushState() updates the URL bar to /about without loading anything.
④ Re-render
React Router's context updates, <Routes> re-renders, the matching <Route> component is shown.

// ── useSearchParams — read/write query strings ────────────
// URL: /products?category=electronics&sort=price&page=2
import { useSearchParams } from "react-router-dom"

function ProductList() {
  const [searchParams, setSearchParams] = useSearchParams()

  const category = searchParams.get("category") ?? "all"
  const sort     = searchParams.get("sort")     ?? "name"
  const page     = Number(searchParams.get("page")) || 1

  const updateFilter = (key, value) => {
    setSearchParams(prev => {
      const next = new URLSearchParams(prev)
      next.set(key, value)
      next.set("page", "1")    // reset to page 1 on filter change
      return next
    })
  }

  return (
    <div>
      <select
        value={category}
        onChange={e => updateFilter("category", e.target.value)}
      >
        <option value="all">All</option>
        <option value="electronics">Electronics</option>
      </select>
      {/* Page 2 → /products?category=electronics&sort=price&page=2 */}
      <button onClick={() => updateFilter("page", String(page + 1))}>Next page</button>
    </div>
  )
}

import { useNavigate, useLocation } from "react-router-dom"

// ── useNavigate — go anywhere programmatically ────────────
function LoginForm() {
  const navigate   = useNavigate()
  const location   = useLocation()

  const handleSubmit = async (e) => {
    e.preventDefault()
    await login(credentials)

    // Navigate to dashboard after login
    navigate("/dashboard")

    // Or go back to where they came from (e.g. protected route redirected here)
    const from = location.state?.from ?? "/dashboard"
    navigate(from, { replace: true })   // replace: true removes /login from history
  }

  return <form onSubmit={handleSubmit}>...</form>
}

05 Nested routes & Outlet — layout components architecture
what nested routes do
Shared layout + swappable content
Nested routes let a parent route render a layout (sidebar, tabs, header) that persists, while child routes render into a specific slot — the <Outlet />. Navigating between child routes only re-renders the outlet content, not the whole layout. Perfect for dashboards, settings pages, and tabbed views.
index routes
Default child when no sub-path matches
An index route renders when the parent path matches exactly but no child path matches. It's the "default" child. For example, at /dashboard (with no sub-path), the index route renders. Navigate to /dashboard/settings and the settings child replaces it.
Outlet context
Pass data from layout to children
The <Outlet context={value}> prop lets a layout route pass data down to any child without prop drilling. Children read it with useOutletContext(). Useful for passing the current user, permissions, or shared state that all children in a section need.

06 Protected routes, 404s & lazy loading real-world

import { Navigate, useLocation, Outlet } from "react-router-dom"

// ── Protected Route — redirect unauthenticated users ──────
// Pattern 1: wrapper component using Outlet
function RequireAuth() {
  const auth     = useAuth()       // your auth hook
  const location = useLocation()

  if (!auth.user) {
    // Redirect to login, but save current location so we can return after login
    return <Navigate to="/login" state={{ from: location }} replace />
  }

  return <Outlet />   // render children if authenticated
}

// In App.jsx — wrap protected routes with RequireAuth
<Routes>
  <Route path="/"      element={<Home />}  />   {/* public */}
  <Route path="/login" element={<Login />} />   {/* public */}

  <Route element={<RequireAuth />}>               {/* auth guard */}
    <Route path="/dashboard" element={<Dashboard />} />
    <Route path="/profile"   element={<Profile   />} />
    <Route path="/settings"  element={<Settings  />} />
  </Route>

  <Route path="*" element={<NotFound />} />       {/* 404 catch-all */}
</Routes>

// ── Role-based protection ─────────────────────────────────
function RequireRole({ role }) {
  const { user } = useAuth()
  if (!user)                 return <Navigate to="/login" replace />
  if (user.role !== role)   return <Navigate to="/forbidden" replace />
  return <Outlet />
}

function matchRoute(pattern, pathname) {
  const patParts  = pattern.split("/").filter(Boolean)
  const pathParts = pathname.split("/").filter(Boolean)
  const params    = {}

  // Handle root "/"
  if (pattern === "/") return pathname === "/" ? { params } : null

  // Wildcard "*" matches everything
  if (pattern === "*") return { params: { "*": pathname.slice(1) } }

  for (let i = 0; i < patParts.length; i++) {
    const seg = patParts[i]

    if (seg === "*") {   // splat
      params["*"] = pathParts.slice(i).join("/")
      return { params }
    }
    if (i >= pathParts.length) return null   // path too short
    if (seg.startsWith(":")) {
      params[seg.slice(1)] = pathParts[i]   // capture param
    } else if (seg !== pathParts[i]) {
      return null   // static segment mismatch
    }
  }
  return patParts.length === pathParts.length ? { params } : null
}

function scoreMatch(pattern) {
  return pattern.split("/").filter(Boolean).reduce((score, seg) =>
    score + (seg === "*" ? 1 : seg.startsWith(":") ? 2 : 3), 0)
}

resolve(pathname) {
  let best = null, bestScore = -Infinity
  for (const route of routes) {
    const match = matchRoute(route.path, pathname)
    if (match) {
      const score = scoreMatch(route.path)
      if (score > bestScore) { best = { route, params: match.params }; bestScore = score }
    }
  }
  return best
}

08 Interview questions + model answers 10 Q&As
Q1How does client-side routing work in a React SPA?▶
model answer
When a user clicks a React Router <Link>, React Router calls e.preventDefault() to stop the browser's default navigation, then calls window.history.pushState() to update the URL bar without making a server request. React Router's context detects the URL change, re-renders the <Routes> component, and the matching <Route>'s element is displayed.

The key insight is that the server only ever serves one HTML file — index.html. All routing logic lives in JavaScript. This is why server configuration matters: any URL must return index.html so React can boot up and handle the route. Direct URL navigation or page refreshes on /about would 404 without this configuration.
Follow-up: "What's the difference between BrowserRouter and HashRouter?" — BrowserRouter uses the real URL path (/about) via the History API. HashRouter uses the URL hash (#/about), which never gets sent to the server. HashRouter works without server configuration but produces uglier URLs and doesn't support server-side rendering.
Q2What is the difference between Link and NavLink?▶
model answer
Both prevent the default page reload and use the History API to navigate. The difference is that NavLink knows whether its to path matches the current URL and provides an isActive boolean to its className and style props.

This makes NavLink ideal for navigation menus where you want to highlight the active page. You pass a function: className={({ isActive }) => isActive ? "active" : ""}. The end prop prevents a parent path (like /dashboard) from matching as active when a child path (like /dashboard/settings) is active — without end, the parent matches all sub-paths.

Use NavLink for navigation, Link for links inside content.
Q3What are nested routes and when do you use them?▶
model answer
Nested routes let a parent route render a persistent layout while child routes render into a specific slot — the <Outlet /> component. The parent renders once and stays on screen; only the outlet's content changes as child routes are navigated.

Use nested routes when: a section of your app has a shared layout (sidebar, tabs, breadcrumbs) that should persist across sub-pages — dashboards, settings panels, profile pages with tabs. Without nested routes, you'd have to re-implement the layout in every page component.

An index route (using the index prop instead of path) defines what renders when the parent path matches exactly but no child path matches — the "default" child view.
Q4How do you implement a protected route?▶
model answer
The standard pattern in React Router v6 is a wrapper component that uses <Outlet />. It checks the auth state and either renders the outlet (allowing the protected children) or returns a <Navigate> component (redirecting to login):

function RequireAuth() { const { user } = useAuth(); const location = useLocation(); if (!user) return <Navigate to="/login" state={{ from: location }} replace />; return <Outlet /> }

Wrap protected routes with this component in the route tree. The state={{ from: location }} saves the intended destination so after login, the app can navigate back with navigate(location.state.from, { replace: true }). The replace on both ensures the login page doesn't appear in the back-button history.
Q5What is the difference between useNavigate and the Navigate component?▶
model answer
useNavigate() returns a function used for imperative, programmatic navigation — called inside event handlers, after async operations, or in response to side effects. You call it: navigate("/dashboard").

<Navigate to="/login" /> is a declarative redirect — a component that, when rendered, immediately navigates. Used in JSX: typically in conditional renders like auth guards (if (!user) return <Navigate to="/login" />), or to redirect old URLs.

Rule of thumb: use useNavigate inside event handlers and effects, use <Navigate /> inside render/return statements. The replace prop on both controls whether the current entry is replaced in history (so back button skips it) or a new entry is pushed.
Q6What is useParams and what type does it return?▶
model answer
useParams() returns an object of key-value pairs for the dynamic segments (params) in the current URL. For a route defined as /users/:id and a URL of /users/42, it returns { id: "42" }.

Important: params are always strings — even when the URL contains a number. If you need a number, parse it: const userId = Number(params.id) or parseInt(params.id, 10).

For routes with multiple params like /posts/:year/:slug, all params are available: { year: "2024", slug: "react-tips" }. The hook is reactive — if the user navigates to a different user profile, the component re-renders with updated params.
Q7When would you use useSearchParams instead of useState for filters?▶
model answer
Use useSearchParams when the filter/search state should be shareable and bookmarkable via URL. If a user filters products by category, then copies the URL to share with someone, that person should see the same filtered view. With regular useState, the filter disappears on page refresh or when the URL is shared.

URL state is also free "state persistence" — if the user navigates away and comes back (using the back button), their filters are restored because the URL contains them. This is expected behaviour on e-commerce sites, search pages, and admin dashboards.

Use useState for ephemeral, non-shareable UI state (dropdown open/closed, modal visibility). Use useSearchParams for state that represents a meaningful, shareable view of data.
Q8How do you implement lazy loading with React Router?▶
model answer
Wrap each page component in React.lazy(() => import('./pages/Dashboard')) — this creates a component that only downloads the JavaScript bundle for that page when it's first rendered. Pair it with <Suspense fallback={<Spinner />}> wrapping the <Routes> to show a loading state while the chunk downloads.

Vite and webpack automatically create separate JavaScript chunks for each lazily imported module. The initial bundle stays small — the user only downloads code for pages they visit. For a large app with many pages, this can reduce the initial load time significantly.

The Suspense boundary can be placed at different levels — one global one wrapping all routes, or per-route for more granular loading states. In React 18, Suspense also works with data fetching via libraries like React Query or the newer use hook.
Q9What is the Outlet component and how does it relate to nested routes?▶
model answer
<Outlet /> is a placeholder in a layout component that renders the matched child route's element. Without an Outlet, a parent route renders its element but the child route's element has nowhere to go — it simply won't appear.

Think of Outlet as a "portal" — the parent defines the surrounding UI (sidebar, header, navigation), and the Outlet is the dynamic region where child content appears. When navigating between /dashboard/analytics and /dashboard/settings, the DashboardLayout component stays mounted; only the Outlet's content swaps.

<Outlet context={data} /> lets the parent pass data to any child without prop drilling — children read it with useOutletContext(). This is useful for passing the current user, permissions, or shared API data to all pages in a section.
Q10Why should you never use a regular anchor tag for internal navigation in React?▶
model answer
A regular <a href="/about"> triggers a full page reload — the browser makes an HTTP request to the server, the server returns HTML, and the entire React application re-initialises from scratch. All in-memory state (auth tokens, loaded data, component state) is lost.

React Router's <Link> intercepts the click, prevents the default behaviour, and uses the History API to update the URL without a page reload. The existing React component tree stays alive, transitions feel instant, and no state is lost.

Correct usage: <Link to="/about"> for internal navigation, <a href="https://external.com"> for external links. External links don't need Link because they intentionally leave the React app.
This is a very common mistake for developers coming from plain HTML. It often manifests subtly — the app "works" because React re-initialises, but you lose auth state, causing unexpected redirects to login, and the UX is noticeably slower.
